# 스크러플 — 4주차 제출용 프로젝트

**26031033 하석현 · 객체지향프로그래밍 · 게임제작**  
구현일: 2026-09-20

꿈에서 헤어진 연인을 찾으며 네 개의 이별 기억을 읽는 작은 탐색 게임입니다. 마지막 만남은 기억의 수에 따라 달라집니다.

## 바로 실행하기

1. ZIP을 **모두 압축 해제**합니다.
2. `Scruple.exe`를 실행합니다.
3. `꿈속으로 들어가기`를 선택합니다. 마우스 클릭 또는 ↑↓ / Enter를 사용합니다.

**실행 파일 옆에 `Assets` 폴더를 함께 두세요.** 프로젝트가 아닌 다른 폴더에서 실행해도 실행 파일 위치를 기준으로 리소스를 읽습니다. 인터넷 연결은 게임 실행에 필요하지 않습니다.

- 실행 대상: Windows 10/11, .NET Framework 4.8 환경
- 기본 창: 1280 × 800. 창 크기를 바꾸면 비율을 유지하고 여백을 둡니다.
- 개발 언어: C#, Windows Forms / System.Drawing / Windows MCI
- 게임 실행과 빌드에는 외부 NuGet 패키지가 필요 없습니다.
- 실제 검증 환경: Windows 11, 기본 .NET Framework C# 컴파일러

## 수업 라이브러리와의 관계

수업 라이브러리 이름과 기존 프로젝트가 제공되지 않아, **독립 실행 가능한 Windows Forms 버전**으로 구현했습니다. 수업 전용 라이브러리 호환성을 확인한 결과물은 아닙니다.

수업 프로젝트로 옮길 때는 `GameForm`의 그리기·키 입력·게임 루프와 `Audio`의 재생 부분을 해당 라이브러리 API로 바꿔야 합니다. `World`, `Monster`, `GameSession`의 규칙은 유지할 수 있지만 `System.Drawing.Point` 참조와 타이밍 연결은 확인해야 합니다.

## 조작

| 입력 | 동작 |
|---|---|
| WASD | 상하좌우 이동, 동시 입력 시 대각선 이동 |
| E | 붉은 기억 읽기, 금빛 빗장 열기, 번호가 있는 문 이용, 마지막 대화 |
| E / Enter / Space | 대화 진행, 엔딩 진행 |
| J | 획득한 기억 다시 읽기. ←→ 또는 버튼으로 선택 |
| Tab | 구역 사이 연결 지도 표시 / 숨기기 |
| Esc | 일시정지 / 재개, 열린 설정·기록·선택 화면 닫기 |
| M | 음소거 / 해제 |
| ↑↓ / Enter | 메뉴 선택 / 실행 |

대화, 기억 기록, 설정, 일시정지 중에는 미로와 괴물의 시간이 멈춥니다. 다른 창으로 전환하면 이동 키를 해제하고 게임을 일시정지합니다. Tab 연결 지도는 작은 오버레이이므로 시간이 계속 흐릅니다.

## 미로 읽기

- **돌로 포장된 길**만 이동할 수 있습니다. 화면 테두리와 실제 충돌 경계가 같습니다.
- **붉은 마름모**: 기억 조각. 네 탐색 구역에 하나씩 있습니다.
- **번호가 있는 원**: 구역 이동 문. 숫자는 도착 구역입니다. 근처에서 E를 누릅니다.
- **금빛 빗장 장치**: E로 열면 아래쪽 출발 통로가 중앙 통로와 연결되고, 중앙 구역으로 가는 문도 열립니다.
- **금색 쇠창살**: 아직 열리지 않은 지름길. 바깥 순환로를 통해 안쪽 장치를 찾아야 합니다.
- 몬스터의 **발견! / 추격 / 수색 / 복귀** 표시는 소리 없이도 상태를 알려줍니다.
- 새벽의 문턱에는 몬스터가 없습니다.

구역 연결은 **달빛 회랑 ↔ 잠긴 서고 ↔ 침묵의 정원 ↔ 마지막 종탑 ↔ 달빛 회랑**의 고리입니다. 각 구역의 빗장을 열면 중앙의 **새벽의 문턱**으로 이어집니다. 마지막 종탑의 중앙 문은 처음부터 열려 있어, 기억이 부족한 결말도 도달 가능합니다. 중앙에서는 네 구역으로 다시 갈 수 있습니다.

기억 획득은 이동 문을 여는 조건이 아닙니다. 탐색 순서는 자유롭고, 놓친 기억을 찾으러 돌아갈 수 있습니다.

## 괴물을 피하는 방법

1. 순찰 경로를 잠시 관찰합니다. 첫 구역에는 괴물 한 마리, 뒤 구역에는 최대 두 마리만 있습니다.
2. 시야에 들어가면 약 0.7초간 발견 예고를 합니다.
3. 플레이어는 추격 중인 괴물보다 조금 빠릅니다. 직선 도주만으로 해결하려 하지 말고 모퉁이를 돌아 시야를 끊으세요.
4. 괴물은 마지막 목격 지점 주변을 수색합니다. 그곳을 벗어나 다른 길로 돌아가세요.
5. 잡히면 해당 구역의 입구부터 다시 시도할 수 있습니다.

발견은 **거리 + 벽에 가려지는지**로 판단합니다. 바라보는 방향에 따른 부채꼴 시야는 이번 버전에 포함하지 않았습니다. 모든 지형은 정해진 구조이며 무작위 생성하지 않습니다.

## 재도전과 결말

**체크포인트:** 문으로 구역에 들어올 때 위치, 네 기억의 획득 상태, 네 지름길의 개방 상태를 저장합니다. 잡히거나 기억 부족 결말에서 재도전하면 그 스냅샷을 그대로 복구합니다. 따라서 **현재 구역에 들어온 뒤 얻은 기억과 지름길은 되돌아가고, 진입 전에 완료한 것은 유지**됩니다. 재입장 직후 2.5초 동안 발견·접촉 보호가 적용됩니다.

이 체크포인트는 실행 중 메모리에만 유지됩니다. 프로그램 종료 또는 시작 화면에서 새 게임을 시작하면 초기화됩니다. 별도의 영구 저장은 없습니다.

- **기억 4개 + 마지막 대화:** 정상 엔딩. E로 장면을 넘겨 마지막 아침까지 봅니다.
- **기억 부족:** 탐색으로 돌아가거나 지금 만날지 선택합니다. 기본 선택은 돌아가기입니다.
- **괴물 접촉:** 즉시 게임오버. 체력·전투·무기 시스템은 없습니다.

## 소스 수정과 빌드

### 간편 빌드

`Build.cmd`를 실행합니다. Windows에 있는 .NET Framework C# 컴파일러로 `Source`의 소스를 묶어 `Scruple.exe`를 생성합니다. **실행 중인 게임은 먼저 종료**해야 실행 파일을 교체할 수 있습니다.

PowerShell에서는 다음과 같이 실행할 수 있습니다.

```powershell
.\build.ps1
```

### Visual Studio

`Scruple.csproj`를 엽니다. `.NET 데스크톱 개발`과 `.NET Framework 4.8 targeting pack`을 갖춘 Visual Studio 환경을 사용합니다. SDK 스타일 프로젝트가 아닌 .NET Framework 프로젝트이므로 `dotnet run`을 기본 실행 방법으로 안내하지 않습니다. Visual Studio 빌드는 이 작업 환경에서 직접 검증하지 않았습니다.

### 파일별 역할

| 파일 | 역할 |
|---|---|
| `Source/Program.cs` | 프로그램 진입, 실행 오류 안내, 테스트 진입점 |
| `Source/World.cs` | 좌표, 조정값, 고정 맵, 공통 충돌, 시야 검사, BFS |
| `Source/Monster.cs` | 순찰·발견·추격·수색·복귀 상태 머신 |
| `Source/GameSession.cs` | 기억, 대화, 체크포인트, 승패와 엔딩 규칙 |
| `Source/GameForm.cs` | Windows 입력, 화면 배율, 실제 게임 루프와 렌더링 |
| `Source/Audio.cs` | 음악 전환, 효과음, 음량, 음소거, 자원 정리 |
| `Source/SelfTests.cs` | 도달성·충돌·AI·진행·오디오 자동 검증과 상태별 화면 저장 |

처음 수정할 곳은 `World.cs`의 `Tuning`입니다. 플레이어 속도, 몬스터 속도, 발견 예고와 수색 시간을 모았습니다. 발견 거리는 `Monster` 생성자에서 구역별로 조금 증가합니다. 맵은 `World.Create()`의 가로·세로 통로로 설계하고, 대사는 `Story`에 모았습니다.

설계와 시연 설명은 `DESIGN.md`, 검증 범위는 `VERIFICATION.md`, 사운드 출처는 `CREDITS.md`를 참고하세요.

## 자동 검사 실행

```powershell
$p = Start-Process -FilePath .\Scruple.exe -ArgumentList '--self-test' -Wait -PassThru
$p.ExitCode
```

종료 코드 0은 통과, 1은 실패입니다. `Tests/automated-results.txt`와 일곱 상태의 PNG가 갱신됩니다. 검사는 잠깐 여러 효과음을 재생하므로 필요한 때 실행하세요. 게임을 플레이 중이라면 먼저 종료한 뒤 실행하는 것이 좋습니다.

## 제출용 Git 태그

기존 저장소가 없어서 임의의 계정으로 업로드하거나 제출 태그를 생성하지 않았습니다. **본인의 과제 저장소 폴더**에 이 프로젝트를 넣은 뒤 변경 내용을 확인하고 다음 예시를 적용하세요. 같은 이름의 태그가 이미 있으면 다른 이름을 선택합니다.

```powershell
git status
git add .
git commit -m "Complete Scruple week 4 input and audio"
git tag -a week4-scruple-v1.0 -m "Week 4 playable build"
git push
git push origin week4-scruple-v1.0
```

태그 링크 형식: `https://github.com/본인계정/저장소/releases/tag/week4-scruple-v1.0` 또는 해당 저장소가 제공하는 태그 페이지. 실제 저장소의 태그 페이지를 열어 파일과 리소스가 들어 있는지 확인한 후 제출하세요.

## 이번 버전의 범위

완성 범위는 작은 탑다운 탐색 게임입니다. 튜닉의 3D 카메라·전투·수직 공간을 구현한 버전은 아닙니다. 이미지는 정적 일러스트를 크기 조절·흔들림·빛과 함께 사용하며, 걷기 프레임 애니메이션이나 실제 포옹 동작 애니메이션은 없습니다. 엔딩의 포옹은 대사와 제공된 작별 일러스트로 연출합니다.

10~15분은 초기 플레이 목표입니다. 인간의 전체 플레이 시간과 체감 난도는 아직 실측하지 않았으므로 완성된 플레이테스트 결과로 주장하지 않습니다. 실제 플레이 후 수업 환경에 맞게 속도와 동선을 조정할 수 있도록 값을 분리했습니다.
