- 실행 파일과 다른 작업 디렉터리에서 자동 검사를 실행해 이미지·사운드 경로가 정상적으로 해석되는 것도 확인했습니다.

## 자동 플레이의 범위와 제한

`Tests/Playthrough.cs`는 게임과 같은 `GameSession.Update()`에 방향과 시간을 전달합니다. 플레이어를 순간이동시키거나 몬스터를 삭제하지 않습니다. 괴물은 같은 시간만큼 정상적으로 움직이고 발견·추격·접촉 판정도 작동합니다. 문 이동, 기억 수집, 재도전 역시 게임의 메서드를 사용합니다.

테스트 경로 선택은 맵과 몬스터의 현재 위치를 아는 비용 기반 탐색입니다. 위험한 칸의 이동 비용을 높여 우회합니다. 도입 대사는 생략하고 기억 대사는 자동으로 넘깁니다. 이 방법으로 **약 92.6초의 시뮬레이션 시간**에 엔딩에 진입했습니다. 이는 이미 길을 아는 테스트 프로그램의 결과이며, 사람의 첫 플레이 시간·체감 난도·플레이테스트 완료를 의미하지 않습니다.

재현:

```powershell
.\Tests\run-playthrough.ps1
```

## 화면 확인

다음 화면은 게임과 같은 `OnPaint()` 렌더 경로로 저장한 후 시각적으로 확인했습니다.

- `01-title.png`: 시작 메뉴와 원본 메뉴 영역의 중복 처리
- `02-play.png`: 길·기억·문·괴물·플레이어·조작 안내
- `03-memory.png`: 기억 대사와 계속 버튼
- `04-ending.png`: 작별 일러스트·대사·꽃잎
- `05-dawn.png`: 마지막 아침 장면
- `06-journal.png`: 획득 기억의 전체 대사 다시 읽기
- `07-settings.png`: 조작 안내·음량·음소거

이 PNG들은 상태를 지정해 렌더한 자료입니다. 정상 엔딩까지 직접 조작한 화면 녹화는 아닙니다.

Computer Use로 실제 실행 창의 시작 화면도 확인했습니다. 이후 사용자 입력 감지로 자동 키 입력이 차단되어, 그 창의 조작을 이어서 자동화하지 않았습니다. 실제 창에서 WASD를 장시간 누르는 조작감, 여러 화면 크기에서의 마우스 클릭, 운영체제 창 전환은 사람의 수동 확인이 남아 있습니다. 입력·포커스 규칙 자체는 위 자동 검사에 포함되어 있습니다.

## 아직 확인하지 않은 것

- 인간의 전체 플레이 시간과 난도: 10~15분은 설계 목표이며 실측 결과가 아닙니다. 자동 경로는 매우 짧으므로 실제 첫 플레이도 목표보다 짧을 수 있습니다.
- 음악을 사람이 직접 들어 평가한 믹싱 품질: 재생 상태와 오류 유무만 확인했습니다.
- 수업 전용 라이브러리 호환성: 라이브러리와 원본 프로젝트가 제공되지 않았습니다.
- 다른 PC와 Visual Studio IDE 빌드: 현재 PC의 기본 컴파일러 빌드만 직접 실행했습니다.
- Git 원격 업로드·제출 태그: 기존 저장소가 없어 실행하지 않았습니다.
