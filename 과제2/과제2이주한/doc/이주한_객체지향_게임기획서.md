# 블락(Block) 게임 기획서

## 1. 게임 개요

| 항목 | 내용 |
| --- | --- |
| 제목 | 블락(Block) |
| 장르 | 2D 리듬게임 |
| 플랫폼 | Windows PC |
| 플레이 인원 | 1인 |
| 조작 | 마우스 / 키보드 방향키 |

`블락`은 화면 중앙에서 사방으로 발사되는 화살표 노트를 보고, 정사각형의 네 변을 방향키로 막는 리듬게임이다.

모든 노트는 중앙의 생성 지점에서 나타나 화살표가 가리키는 방향으로 이동한다. 플레이어는 노트가 정사각형의 변에 도착하는 순간 해당 방향키를 입력해 노트가 바깥으로 빠져나가는 것을 막아야 한다.

---

## 2. 핵심 재미

노트가 생성되는 순간에는 모든 노트가 중앙에 모여 있기 때문에 방향과 색을 한눈에 확인할 수 있다. 그러나 노트가 사방으로 퍼진 뒤에는 화면 전체를 한눈에 보기 어려워진다. 플레이어는 중앙에서 확인한 정보를 기억한 뒤 여러 방향을 살피거나, 노트의 색을 통해 도착 시점을 예상해야 한다.

블락의 핵심 재미는 다음 과정에서 만들어진다.

1. 중앙에 생성된 노트의 방향과 색을 한눈에 확인한다.
2. 노트가 사방으로 흩어지기 전에 각 노트의 도착 순서를 예상한다.
3. 화면 여러 곳을 살피며 필요한 방향을 놓치지 않는다.
4. 음악과 예상한 타이밍에 맞춰 방향키를 입력한다.
5. 자신의 예상이 실제 박자와 맞았을 때 성취감을 얻는다.

따라서 이 게임은 화면 끝에 도착한 노트만 보고 반응하는 게임이 아니다. **노트가 생성되는 순간에 정보를 읽고, 흩어진 뒤에는 그 정보를 기억하며, 색상별 속도를 바탕으로 타이밍을 예측하는 게임**이다.

조작에는 네 개의 방향키만 사용하기 때문에 규칙은 단순하다. 대신 동시에 확인해야 하는 방향이 많아질수록 시선 분배와 기억, 박자 예측이 중요해진다.

---

## 3. 기본 플레이

1. 음악과 함께 플레이가 시작된다.
2. 정사각형 중앙의 생성 지점에서 화살표 노트가 나타난다.
3. 화살표 노트는 자신이 가리키는 방향으로 이동한다.
4. 플레이어는 노트의 색으로 이동 속도를 구분한다.
5. 노트가 정사각형의 변에 도착할 때 같은 방향의 키를 입력한다.
6. 입력한 시각과 노트의 도착 시각을 비교해 판정한다.
7. 입력하지 못한 노트는 정사각형 밖으로 빠져나가며 Miss 처리된다.
8. 모든 노트가 끝나면 결과 화면을 표시한다.

---

## 4. 화면 구성

플레이 화면의 중심에는 노트가 생성되는 지점이 있으며, 그 주위를 정사각형 판정 영역이 둘러싼다.

```
               위쪽 판정 변
            ┌────────────────┐
            │                │
            |                |
 왼쪽 판정 변│       ●        │오른쪽 판정 변
            │     생성지점    │
            │                │
            └────────────────┘
               아래쪽 판정 변
```

- 중앙 생성 지점: 모든 노트가 처음 나타나는 장소
- 정사각형 내부: 노트가 이동하는 공간
- 정사각형의 네 변: 노트를 막는 판정 지점
- 화면 상단: 현재 점수와 콤보
- 중앙 하단: Perfect, Good, Bad, Miss 표시

노트가 이동한 뒤에는 서로 다른 방향을 동시에 확인해야 하므로, 화면 중앙과 네 변이 명확하게 구분되어야 한다. 모든 Scene은 같은 배경을 사용하며, 배경과 장식은 노트와 충분한 명암 차이를 두어 화살표의 방향과 색을 쉽게 알아볼 수 있도록 한다.

---

## 5. 조작

시작 Scene과 종료 Scene의 버튼은 마우스 왼쪽 버튼으로 클릭한다.

| 입력 | 막는 위치 |
| --- | --- |
| `↑` | 위쪽 변 |
| `↓` | 아래쪽 변 |
| `←` | 왼쪽 변 |
| `→` | 오른쪽 변 |

키를 입력하면 해당 변이 짧게 밝아진다. 이를 통해 플레이어가 어떤 방향을 눌렀는지 바로 확인할 수 있다.

서로 다른 방향의 노트가 함께 도착할 수 있기 때문에 두 개 이상의 방향키를 동시에 입력할 수 있다. 롱 노트를 누르고 있는 동안에도 나머지 방향키로 다른 노트를 처리할 수 있다.

---

## 6. 노트 시스템

### 6.1 공통 형태

모든 노트는 꺾쇠(`<`) 형태의 화살표를 사용한다. 꺾쇠가 가리키는 방향은 노트가 이동할 방향이자 플레이어가 입력해야 할 방향이다.

속도가 달라도 노트의 모양과 크기는 달라지지 않는다. 노트의 종류는 색으로만 구분한다. 따라서 플레이어는 화살표의 방향으로 입력 위치를 판단하고, 색으로 이동 방식과 이동 시간을 판단한다.

### 6.2 색상과 속도

회색 노트가 중앙에서 생성되어 판정 변에 도착하기까지 걸리는 시간을 **기준 이동 박자**로 정한다. 빨간색과 파란색 노트의 이동 시간 및 속도 변화는 이 기준을 바탕으로 구분한다.

| 색상 | 종류 | 도착까지 걸리는 시간 | 움직임 |
| --- | --- | --- | --- |
| 회색 | 일반 노트 | 기준 이동 박자 1배 | 생성부터 도착까지 일정한 속도로 이동한다. |
| 빨간색 | 가속 노트 | 기준 이동 박자 1배 | 회색 노트와 동시에 생성되면 같은 시각에 도착하지만, 강한 Ease-In 커브에 따라 처음에는 느리고 점점 빨라진다. |
| 파란색 | 지연 가속 노트 | 기준 이동 박자 3배 | 전체 이동 시간의 처음 2/3 동안은 느리게 이동하고, 시간 기준 2/3 지점부터 커브가 적용되어 점점 빨라진다. |

빨간색 노트는 회색 노트보다 빨리 도착하는 노트가 아니다. 두 노트의 생성 시각이 같다면 판정 변에 도착하는 시각도 같다. 다만 빨간색은 초반에 이동한 거리가 짧고 후반에 빠르게 남은 거리를 이동하기 때문에, 화면에서 느껴지는 속도의 변화가 크다.

파란색 노트는 회색 노트보다 세 배 긴 시간 동안 이동한다. 가속이 시작되는 지점은 이동한 거리가 아니라 **생성 후 흐른 시간**으로 판단한다. 전체 이동 시간을 3등분했을 때 처음 2개 구간은 느리게 이동하고, 마지막 1개 구간이 시작되는 순간부터 점차 가속한다.

색상은 단순한 장식이 아니라 노트가 어떤 시간 규칙으로 움직이는지 알려 주는 정보다. 플레이어는 빨간색을 보면 후반의 급가속을 예상하고, 파란색을 보면 긴 이동 시간과 마지막 구간의 가속을 고려해 입력 시점을 판단해야 한다.

회색 노트의 기준 이동 박자와 빨간색·파란색 노트에 적용되는 커브의 강도는 고정하지 않는다. 실제 플레이에서 노트를 확인하고 예측할 시간이 충분한지 테스트한 뒤 조정한다. 단, 빨간색은 회색과 이동 시간이 같고 파란색은 회색의 세 배라는 색상 간 시간 관계는 유지한다.

노트가 사방으로 흩어진 뒤에는 모든 노트를 한눈에 보기 어렵기 때문에 생성 순간에 확인한 색상 정보가 중요해진다.

### 6.3 단타 노트

단타 노트는 하나의 꺾쇠 형태로 표현한다. 노트가 판정 변에 도착하는 순간 해당 방향키를 한 번 누르면 된다.

### 6.4 롱 노트

롱 노트는 단타 노트와 같은 꺾쇠 두 개 사이를 몸통으로 연결한 형태로 표현한다. 앞쪽과 뒤쪽 꺾쇠는 크기와 색상이 같으며, 유지 박자에 따라 가운데 몸통의 길이만 달라진다.

플레이어는 앞쪽 꺾쇠가 판정 변에 도착할 때 방향키를 누르고, 뒤쪽 꺾쇠가 판정 변에 도착할 때까지 키를 유지해야 한다.

```text
단타 노트 : <
롱 노트   : <====<
```

롱 노트는 길이와 관계없이 판정과 정확도 계산에서 하나의 노트로 취급한다. 길이가 길다고 더 많은 점수나 정확도를 얻지는 않는다. 시작 입력의 판정은 앞쪽 꺾쇠가 도착한 시각을 기준으로 결정하고, 끝까지 유지했을 때 점수와 콤보를 확정한다. 중간에 키를 놓으면 Miss로 처리한다.

## 7. 박동 연출

정사각형, 중앙 생성 지점, 화면에 존재하는 모든 노트는 음악의 박자에 맞춰 작게 박동한다.

박동은 크기가 순간적으로 조금 커졌다가 원래 크기로 돌아오는 형태로 표현한다. 이 연출은 단순한 장식이 아니라 화면 전체가 같은 박자를 공유하고 있다는 사실을 보여 준다.

- 정사각형의 박동은 현재 박자를 시각적으로 전달한다.
- 생성 지점의 박동은 새로운 노트가 시작되는 중심을 강조한다.
- 노트의 박동은 음악과 노트의 움직임이 연결되어 있음을 보여 준다.

모든 요소의 박동이 지나치게 크면 노트 위치를 알아보기 어려우므로, 방향과 판정 지점을 방해하지 않는 작은 크기 변화만 사용한다.

---

## 8. 판정 및 정확도

### 8.1 판정

노트가 판정 변에 도착해야 하는 시각과 플레이어가 방향키를 입력한 시각의 차이로 판정을 결정한다.

| 판정 | 목표 시각과의 차이 | 정확도 |
| --- | --- | --- |
| Perfect | 50ms 이내 | 100% |
| Good | 50ms 초과 100ms 이내 | 70% |
| Bad | 100ms 초과 150ms 이내 | 30% |
| Miss | 150ms 초과 또는 입력 실패 | 0% |

빠르게 입력한 경우와 늦게 입력한 경우 모두 목표 시각과의 차이를 기준으로 동일하게 판정한다. 판정마다 정확도를 고정해 플레이어가 결과를 쉽게 이해할 수 있도록 한다.

판정할 수 있는 노트가 없는 상태에서 방향키를 입력하면 해당 입력은 무시한다. 같은 방향의 노트가 여러 개 판정 범위 안에 있으면 입력 시각과 목표 시각의 차이가 가장 작은 노트를 판정한다.

### 8.2 전체 정확도

각 노트는 판정에 따라 100%, 70%, 30%, 0% 중 하나의 정확도를 가진다. 곡이 끝난 뒤 모든 노트의 정확도를 더하고 전체 노트 수로 나누어 최종 정확도를 계산한다.

```
전체 정확도 = 모든 노트 정확도의 합 ÷ 전체 노트 수
```

롱 노트도 길이에 관계없이 하나의 노트로 계산한다. 따라서 긴 롱 노트가 전체 정확도에 지나치게 큰 영향을 주지 않으며, 모든 노트가 동일한 비중을 가진다.

롱 노트를 끝까지 유지하면 입력한 시작 시각을 기준으로 정확도를 계산하고, 중간에 키를 놓으면 Miss로 처리한다.

계산된 전체 정확도는 소수점 첫째 자리로 반올림해 표시한다.

---

## 9. 점수와 콤보

### 9.1 점수

한 곡의 최대 점수는 전체 노트 수와 관계없이 **1,000,000점**으로 정한다. 전체 노트를 모두 Perfect로 처리하면 1,000,000점을 획득한다.

노트 하나의 최대 점수는 전체 노트 수에 따라 결정된다.

```
노트당 최대 점수 = 1,000,000 ÷ 전체 노트 수
```

각 노트의 실제 획득 점수는 판정 정확도를 노트당 최대 점수에 적용해 계산한다.

| 판정 | 정확도 | 획득 점수 |
| --- | --- | --- |
| Perfect | 100% | 노트당 최대 점수 × 1.0 |
| Good | 70% | 노트당 최대 점수 × 0.7 |
| Bad | 30% | 노트당 최대 점수 × 0.3 |
| Miss | 0% | 0점 |

```
최종 점수
= 모든 노트의 판정 정확도 합
  ÷ (전체 노트 수 × 100)
  × 1,000,000
```

계산된 최종 점수에 소수점이 발생하면 반올림해 정수로 표시한다.

점수에 영향을 주는 요소는 노트 판정뿐이며, 콤보 배율이나 기믹 보너스 같은 추가 점수는 존재하지 않는다.

따라서 같은 수의 노트를 처리했다면 더 정확하게 입력한 플레이어가 더 높은 점수를 받는다. 롱 노트도 길이와 관계없이 하나의 노트 점수만 가진다.

### 9.2 콤보

Perfect, Good, Bad 판정을 받으면 콤보가 1 증가하고, Miss가 발생하면 콤보가 끊어진다. 롱 노트의 콤보는 끝까지 유지했을 때 증가한다. 콤보는 점수에 추가 배율을 제공하지 않으며, 플레이를 얼마나 안정적으로 이어 갔는지 보여 주는 기록으로만 사용한다.

플레이 중에는 현재 콤보를 표시하고, 플레이 종료 후에는 가장 높았던 최대 콤보를 결과 화면에 표시한다.

---

## 10. 화면 기믹

화면 기믹은 노트의 정답 방향이나 판정 기준을 바꾸지 않는다. 플레이어가 노트를 확인하는 방법만 변화시켜 기본 규칙 안에서 새로운 긴장감을 만든다.

### 10.1 화면 확대

게임 화면이 중앙을 기준으로 확대되어 정사각형의 각 변이 화면 밖으로 벗어난다. 플레이어는 중앙에서 노트가 생성되는 모습은 볼 수 있지만 실제 판정 지점은 볼 수 없다.

이때는 노트가 생성될 때 확인한 방향과 색을 기억하고, 음악과 속도를 바탕으로 도착 시점을 예상해야 한다.

### 10.2 중앙 가림

화면 중앙에 잉크나 먼지가 묻은 것 같은 가림 효과가 나타난다. 생성 지점은 보이지 않고 정사각형의 각 변에 가까워진 노트만 확인할 수 있다.

화면 확대와 반대로 노트의 초기 정보를 숨기는 기믹이다. 플레이어는 뒤늦게 보이는 화살표의 방향과 색을 빠르게 읽어야 한다.

---

## 11. 채보 관리 시스템

음악에 맞춰 배치한 노트가 게임에서 동일하게 재생될 수 있도록 하나의 JSON 채보 파일로 관리한다. 채보 파일에는 다음 정보가 포함된다.

- 곡의 BPM과 시작 오프셋
- 노트의 도착 박자
- 화살표의 방향
- 회색·빨간색·파란색 구분
- 단타·롱 노트 구분
- 롱 노트의 유지 박자

채보는 반 박과 1/4박 단위를 지원한다.

게임은 JSON 채보에 기록된 박자와 노트 정보에 따라 플레이를 진행한다. 채보와 게임 규칙을 분리해 관리하므로 노트 배치를 수정하더라도 게임의 다른 시스템은 영향을 받지 않는다.

```text
JSON 채보 불러오기
                 ↓
박자에 맞춰 노트 생성 및 이동
                 ↓
저장된 방향과 종류에 따라 판정
```

기준 이동 박자와 색상별 커브 강도는 채보 제작 단계에서 확정하지 않는다. 게임 플레이 테스트를 통해 적절한 값을 찾고, 설정을 변경해도 기존 채보의 노트 배치가 유지되도록 한다.

---

## 12. 게임 화면 흐름

블락에는 하나의 곡과 하나의 채보를 사용한다. 게임은 시작, 플레이, 종료의 세 Scene으로 구성한다.

```text
시작 Scene
  ↓ 게임 시작 버튼 클릭
플레이 Scene
  ↓ 곡과 모든 노트 종료
종료 Scene
  ↓ 돌아가기 버튼 클릭
시작 Scene
```

### 12.1 시작 화면 (Title Scene)

![시작 화면](images/01_title_scene.png)

게임 제목, `게임 시작` 버튼, `게임 종료` 버튼을 표시한다. 버튼은 마우스로 클릭한다.

### 12.2 플레이 화면 (Gameplay Scene)

![플레이 화면](images/02_gameplay_scene.png)

음악에 맞춰 노트를 처리하며 현재 점수와 콤보를 표시한다.

### 12.3 종료 화면 (Result Scene)

![종료 화면](images/03_result_scene.png)

결과 등급, 최종 점수, 전체 정확도, 최대 콤보, `돌아가기` 버튼을 표시한다.

`돌아가기` 버튼을 클릭하면 시작 Scene으로 이동한다. 다시 플레이하려면 시작 Scene에서 `게임 시작` 버튼을 클릭한다.

---

## 13. 결과 화면

플레이가 끝나면 다음 세 가지 핵심 결과를 크게 표시한다.

- 결과 등급
- 최종 점수
- 전체 정확도
- 최대 콤보

결과 등급은 소수점 첫째 자리로 반올림해 표시한 전체 정확도를 기준으로 결정한다.

| 등급 | 전체 정확도 |
| --- | --- |
| S | 97% 이상 |
| A | 90% 이상 97% 미만 |
| B | 80% 이상 90% 미만 |
| C | 70% 이상 80% 미만 |
| F | 70% 미만 |

보조 정보로 Perfect, Good, Bad, Miss의 개수를 함께 표시할 수 있다. 그러나 별도의 콤보 보너스, 기믹 보너스, 추가 점수 항목은 표시하지 않는다.

점수는 전체적인 성과를, 정확도는 입력 타이밍의 정밀함을, 최대 콤보는 플레이를 안정적으로 이어 간 정도를 보여 준다. 세 결과가 서로 다른 관점에서 한 번의 플레이를 설명하기 때문에 플레이어는 다음 도전에서 무엇을 개선할지 판단할 수 있다.

종료 Scene의 `돌아가기` 버튼을 클릭하면 시작 Scene으로 이동한다. 종료 Scene에서는 바로 재도전하지 않는다.

---

블락은 중앙에서 정보를 한눈에 확인할 수 있는 순간과, 노트가 사방으로 흩어져 여러 곳을 살펴야 하는 순간의 차이를 이용한 리듬게임이다. 플레이어는 화살표의 방향으로 입력 위치를 이해하고, 색상으로 이동 속도를 구분하며, 음악을 통해 실제 도착 시점을 예상한다.

화면을 넓게 살피는 관찰력, 생성 순간의 정보를 기억하는 능력, 색상별 속도를 이용한 타이밍 예측이 함께 요구된다는 점이 블락의 가장 큰 특징이다.

## 14. 리소스 구성

```text
resource/
├─ image/
│  ├─ background/
│  ├─ logo/
│  ├─ note/
│  ├─ ui/
│  └─ effect/
├─ audio/
│  ├─ bgm/
│  └─ sfx/
└─ chart/
```

### 필요한 이미지

- 모든 Scene에 공통으로 사용하는 배경
- 게임 로고
- 버튼 기본·마우스 오버·클릭 상태
- 정사각형 판정 영역
- 중앙 생성 지점
- 방향별 회색·빨간색·파란색 노트
- 색상과 방향에 맞는 롱 노트 연결 몸통
- Perfect, Good, Bad, Miss 판정 효과
- 중앙 가림 효과 이미지
- S, A, B, C, F 결과 등급
- 종료 Scene 결과 패널

점수, 콤보, 정확도처럼 플레이에 따라 값이 달라지는 문자는 이미지에 포함하지 않고 게임의 글자 출력 기능을 사용한다.

### 필요한 오디오 및 데이터

- 배경 음악 1곡
- 버튼 클릭 효과음
- 노트 판정 효과음
- JSON 채보 1개
